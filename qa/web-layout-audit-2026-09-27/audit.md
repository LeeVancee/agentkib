# Web 布局审查 · 2026-09-27

结论：桌面结构基本合理，手机主会话页需要优化信息层级，尚不宜称为已完成手机体验验收。此次只做审查，没有修改产品代码、部署、授权或 TUN。

## 范围和证据

- 实际线上托管首页及局域网入口：remote.agentkib.com。
- 当前 apps/web/dist 构建的会话、设置、执行管理、上下文、审批：仅本机隔离合成数据，不连接真实 Codex，也不执行任何任务。
- 390×844 手机 CSS 视口、390×560 短屏设置布局、1440×900 桌面对照。手机视口模拟不等于 iPhone Safari / Android Chrome 真机验收；未测软键盘、安全区、读屏器、完整键盘循环和全部语言。
- 真实设备控制地址本轮返回 ERR_CONNECTION_CLOSED；这只说明本轮无法访问，不能据此判定中继整体故障。文件与产物实际预览未覆盖。
- 合成资源、模型和能力用于布局展示；不能据此推断官方宿主支持程度。空白正文来自简短测试会话，不作为“内容不足”缺陷。

## 分步骤健康度

1. 托管首页：基本合理。远程连接步骤与次级局域网入口分开，未制造不存在的全网配对入口。手机顶部语言/外观占一行，可后续收进设置。证据 08。
2. 局域网连接：需优化。说明、步骤、重复开通提示都在表单之前，390×844 首屏看不到确认和连接按钮。保留风险确认，将步骤折叠、表单前置。证据 09。
3. 会话目录：基本合理。搜索、按工作区分组、新建任务、退出授权均有明确位置；只测试四条合成会话，大目录效率另测。证据 10。
4. 会话阅读与发送：需优先优化。双页头与工具条占据顶部空间，“历史只读”容易误导，手机输入工具换两行。证据 01、11。
5. 设置和上下文：需优化。常规竖屏设置可完整显示；短屏可滚动，但应用按钮不常驻；原始英文枚举与禁用说明需要改进。证据 02、03、06。
6. 审批和执行管理：部分合理。审批自动出现，显示命令、目录、权限及持久规则确认；长审批需滚动。执行归属与 Codex 控制分散，原生术语过多。证据 04、05、07。

## 按优先级的发现

### 1. P2：手机主会话页常驻层级过多

390×844 下依次是 64px 全局页头、64px 会话页头、状态行、工具条；输入框约占底部 230px。阅读区域被两端压缩，软键盘出现后的实际体验还需真机验证。

建议：手机合并品牌栏和会话栏，保留返回、标题、待处理徽标和更多菜单。连接状态并入标题副行；文件作为直接入口；执行归属、重命名、归档、分支等收进“会话操作”。输入区使用“添加 / 模型与强度 / 发送”紧凑排列，目标入口放入添加菜单，活动目标才显示状态条。

位置：session-layout.tsx:42；session-reader.tsx:54、79、91；codex-composer.tsx:306；codex-session-controls.tsx:277。证据 01、11。

### 2. P2：“历史只读”与可发送会话并列，权限状态容易被误解

它实际指历史消息不可编辑，却置于会话主状态位置，用户容易理解为整段会话不可操作。下方又有可编辑发送框和实验控制说明。

建议移除常驻“历史只读”，仅在必要位置说明历史不可编辑；主状态统一表达“已连接 · 可发送 / 正在执行 / 待审批 / 无控制权限 / 已断线”。发送禁用时就近给出具体原因，避免用户靠推测。

位置：session-reader.tsx:79；i18n/index.ts:39。证据 01。

### 3. P2：“执行管理”和“Codex 控制”没有清晰的用户心智边界

前者打开“执行归属”，后者混有能力诊断、继续恢复、改名、归档、分支和队列。用户需要记忆实现概念才能找到操作；两处“核对结果/原生状态”也难区分。

建议统一为“会话操作”，分成会话管理、执行归属、诊断三组。执行归属作为状态展示，交接作为明确动作；能力和原生详情折叠到诊断。保留文件入口的独立性。

位置：session-reader.tsx:91；managed-tasks.tsx:262、274；codex-tools.tsx。证据 04、05。

### 4. P2：触屏上的不可用说明和上下文用量不够可发现

多个 disabled select/button 的原因只放在 title 中；10px 的上下文百分比也是普通 span，其详细 token 数主要依靠 title（设置面板中另有完整数值）。触屏无法像鼠标那样方便悬停，键盘也不能聚焦该 span。上下文列表还直接输出 file/directory/skill 和 not_native_verified 等原始值。

建议禁用字段旁展示本地化原因；用量改成可点按、有明确名称的按钮或信息卡，提供“上下文已用 51%”。资源种类和能力错误映射成人话，原始码只放技术详情。默认字号适当提高；不据本次截图宣称 WCAG 不合规。

位置：codex-session-controls.tsx:274、287、332、362、377、391、423、474、661、673。证据 01、02、06。测试资源禁用状态由合成能力控制，仅用于检查呈现方式。

### 5. P2：短屏设置的主操作随整个弹窗一起滚动

390×560 DOM 检查：dialog top=42、height=476、scrollHeight=584、overflow-y=auto。说明它可滚动，并非完全不可访问；但“应用到下一轮”位于当前可视区之外，手机用户要滚到最下方才能提交。

建议手机使用底部面板或全屏设置；标题和应用操作常驻，中间表单独立滚动。保留恢复默认的次级位置和“下一轮生效”的含义。审批长列表也应保持明确关闭/返回路径，但不要把不同授权范围压成一个含糊的允许按钮。

位置：components/ui/dialog.tsx:39；codex-session-controls.tsx:454。证据 02、03、07。

### 6. P3：局域网入口将说明置于操作之前

手机首屏依次展示大标题、介绍、三步说明、第二个标题及重复开通要求，地址输入直到下半屏，风险确认和连接按钮在折叠线以下。

建议表单前置，仅保留简短使用条件；“如何获取地址”改为可展开帮助，明文风险和确认继续紧邻提交操作。不要为了节省高度移除风险确认。

位置：features/connection/connection-page.tsx:110。证据 09。

## 保留的设计

- 桌面左目录、右会话、底部输入的总体结构。
- 默认浅色、克制边框与较清晰的卡片分组。
- 托管首页与电脑同源会话职责分开。
- 上下文菜单区分手机上传和电脑资源。
- 审批展示命令、目录、权限范围，持久授权有额外确认。

## 下一轮建议

先处理发现 1–4，统一手机主界面的信息层级，再处理弹窗和局域网表单。验收应补充：长中文标题、长模型名、长会话、多个审批、加载/断线/只读、320px 窄屏、真实软键盘和四语言。已有功能不必重建，也不应借布局修改扩大权限。
