# 连接原 Claude Code 会话

AgentKib 的原会话连接和托管执行是两条独立路径。原会话连接通过第一方 Mods 插件观察并控制用户已经启动的 Claude Code；不会启动第二个 `--resume` 进程。托管执行仍由 AgentKib 管理自己的 CLI 进程，外部历史交接继续要求停止确认。

## 首次连接

本期原生连接限 macOS、Claude Code **2.1.301**。插件版本为 **0.1.0**。其他版本及 Windows/Linux 不自动开放控制；组织策略、safe mode 或禁用 hooks 可能阻止插件加载。

1. 在桌面打开所选 Claude 会话的执行管理，查看“连接原 Claude 终端”。
2. 按面板显示的路径添加本地 `agentkib-local` marketplace，主动安装 `agentkib-bridge`。AgentKib 不自动安装或修改个人配置。
3. 已打开的终端执行 `/reload-plugins`。新建隔离测试会话也可用 `--plugin-dir` 加载随应用提供的插件目录。
4. 在 AgentKib 生成一次性连接指令，在对应原终端执行 `/agentkib-connect …`。挑战只绑定所选 UUID 和工作区，120 秒有效，成功消费或断开后失效。

插件连接到 Runtime 的私有 Unix socket。应用数据中的绑定文件只允许当前用户读写；长期凭据不进入 Renderer、Web、URL 或日志。请勿把连接指令交给其他终端。连接和查看状态不发送模型请求。

## 能力和状态

| 界面状态 | 执行者 | 操作 |
| --- | --- | --- |
| 已连接原会话 | 已经运行的 Claude Code | 开放观察和当前轮次取消；文本发送暂不开放 |
| 由 AgentKib 执行 | AgentKib 自己管理的 CLI | 保留既有托管发送、审批、问答、附件及其他已验证能力 |
| 仅查看历史 | 尚无已连接执行者 | 可阅读历史；桌面提供原终端连接指引及独立的托管交接入口 |

原连接模式不显示停止原终端及交接确认。连接失败不会自动另起同 UUID 进程；用户明确选择更换执行者时，才使用原有托管交接。

首期原连接模式的**审批和问题仍在原终端处理**，AgentKib 只显示等待原因。附件、上下文资源、队列、目标、改名、分叉及设置不因连接成功而获得能力。工具过程复用摘要展示，不把历史工具记录当成可执行调用；没有原生报告的上下文用量显示暂无数据。

原生日志仍是完整历史来源。插件的近期快照及有界流缓冲不是完整导出；事件缺口会暂停控制并请求新快照，不伪造遗漏内容。隐藏推理不进入桥接消息。

插件在执行中重新加载时，可能尚未取得当前轮次 ID。此时界面保留“正在执行”，说明轮次尚未核实，并关闭取消；后续原生轮次事件才能恢复对应控制。曾触发审批但无法核实授权结果时，界面提示查看原终端，不把它表示为仍在等待审批。Claude 2.1.301 的运行中自动文件热加载在本轮原生实验中未触发，不能保证立即恢复该轮流事件；空闲重载与故障注入测试分别记录。

## 并发、重连和退出

- 桌面和 Web 复用同一 Runtime 连接和持久回执。原生实验确认 `$.prompt.submit` 可能等待终端空闲，未提供可验证的原子空闲门禁。因此本期产品不开放原会话发送，避免隐式排队；隔离实验中的成功发送不提升该能力。请在原终端发送，AgentKib 同步观察。
- 发送已接受与本轮已完成分别记录。失去确认后保留待核对，不自动重发；仅看到空闲状态不足以证明旧操作完成。
- 取消绑定原生轮次 ID，不能用旧按钮取消新的轮次。取消不通过结束原终端实现。
- 插件重载、`/clear`、`/resume`、`/branch` 和身份变化会废止旧连接代际与表单。UUID 和工作区在命令派发前再次核对。
- 浏览器断线不停止本机执行。AgentKib 退出只关闭自己的桥接连接；原终端继续运行。再次启动后核对原操作，不回放旧命令。
- 桌面断开连接会同时撤销未消费的重连挑战，旧凭据不能恢复连接。

Web 仅能使用桌面已经建立且当前授权允许的连接，不能安装插件、生成连接码或提交本机路径。关闭会话索引、来源失效或撤销设备权限后，相关内容与控制按原权限边界失效。
