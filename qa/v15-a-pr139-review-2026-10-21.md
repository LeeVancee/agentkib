## CI 跟进：Windows ARM64 辅助测试预算（2026-10-21）

`af1f8e7fa` 的五个检查中，Ubuntu ARM64、Fedora x64、Windows x64 和 Test/lint/build 均通过。唯一失败为 [Windows ARM64 job 119297057187](https://github.com/starroyhq/agentkib/actions/runs/39621830301/job/119297057187)：在 `node --test .github/scripts/*.test.mjs` 中，首个 PowerShell 原生声明测试的 `spawnSync pwsh` 达到原有 30 秒总预算，耗时 30146.958ms；后续真实 Windows 文件探测通过（7577.994ms）。同提交 x64 的声明测试为 5200.056ms、真实文件探测 6617.949ms。

旧日志可确认失败在独立 PowerShell 测试进程，未进入后面的原生 NSIS、类型检查和 backend gate。由于旧测试未记录阶段，不能断言已经定位到 `Add-Type`，也不能把一次重跑成功当作根因证据。

- Windows ARM64 / x64 的 helper 步骤均显式使用 `--test-concurrency=1`，完整 `*.test.mjs` glob 和后续 NSIS / typecheck / backend gate 保留；未修改 Linux 调度、生产 PowerShell 或卸载实现。
- 首个初始化测试在合成临时文件记录 `entered → parse → load → compile → reinitialize → marshal → complete` 及单调耗时；在 finally 中仅输出通过白名单、顺序和数值校验的摘要。无 trace 时只输出不可用，不打印路径、原始 trace 或任意异常文本。临时文件通过预注册的 `t.after` 清理。
- 保留 `runPowerShell` 的 **30000ms**、可用性探测 **15000ms**、stderr 无任意异常、编译与幂等初始化、结构尺寸，以及全部原生文件锁/字节/属性/用户数据断言。不重试失败进程，不增加预算，不使用 continue-on-error。
