## English

This guide covers local development, validation, and packaging for the current Electron desktop application. Contributor workflow and pull request expectations remain in [CONTRIBUTING.md](../CONTRIBUTING.md).

### Prerequisites

- Node.js 22
- pnpm 10.8.1, as pinned by the root `packageManager` field
- Rust stable with `rustfmt` and `clippy`
- Git

Platform-native build dependencies:

- **macOS 13.3+**: Xcode Command Line Tools
- **Windows 11**: Rust MSVC, Visual Studio Build Tools 2022 with Desktop development with C++, and a Windows 10 or 11 SDK. Follow the [Windows guide](WINDOWS.md).
- **Ubuntu 22.04**: `build-essential`, `pkg-config`, `libssl-dev`, and `libgtk-3-dev`
- **Fedora 42**: GCC/G++, Make, OpenSSL and pkg-config development packages, GTK 3 development packages, and RPM packaging tools. The exact CI baseline is in [linux.yml](../.github/workflows/linux.yml).

Enable the pinned pnpm version, then install dependencies from the repository root:

```bash
corepack enable
corepack prepare pnpm@10.8.1 --activate
pnpm install --frozen-lockfile
```

### Architecture

AgentKib is one desktop application assembled from several cooperating parts:

| Part                  | Location                                                          | Responsibility                                                                                                             |
| --------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Electron main process | `apps/desktop/electron/main/`                                     | Window lifecycle, tray, native shell integration, updates, runtime hosting, and privileged IPC                             |
| Electron preload      | `apps/desktop/electron/preload/`                                  | Narrow bridge exposed to the renderer                                                                                      |
| React renderer        | `apps/desktop/src/`                                               | Routes, screens, state, and user interaction                                                                               |
| TypeScript backend    | `packages/backend/`, `apps/desktop/electron/backend-entry.ts`     | Application settings, workspace/discovery writes and cached reads in an independently restartable Electron utility process |
| Rust Runtime          | Cargo package `agentkib-runtime`                                  | Schema upgrades, quota/storage collection and remaining modules                                       |
| Quota sidecar         | Prepared under `apps/desktop/resources/quota/`                    | Platform-specific local quota collection                                                                                   |
| Runtime protocol      | Generated by `apps/desktop/scripts/generate-runtime-protocol.mjs` | Keeps TypeScript messages aligned with the Rust protocol before development and builds                                     |

The Electron main process starts both backends and mediates renderer access through validated IPC. During the migration, `runtime-router.ts` explicitly assigns each method to one backend. TypeScript owns workspace add/refresh/exclude/restore, scan-root management, discovery orchestration and persistence/reports, cached lists, application preferences, onboarding and quota visibility settings. TypeScript also owns native workspace asset scans and manifest import, effective context previews for all nine Agents, diagnostic reports/summaries and repair planning, reviewed change application with backups and rollback, catalog and memory operations, Git summary/history/files/diff, cached session lists/status and native event reads for all seven providers, insight collection and incremental import, Git commit/identity statistics, cached insight views and breakdowns, achievement reads/unlock persistence and Git identity settings. Git commands run asynchronously with bounded output and timeouts. The Codex collector checkpoints salted file/database identities, reads append-only JSONL tails, rebuilds truncated or replaced sources, retains incomplete last-good data and atomically commits checkpoints with usage events. Claude stats-cache, OpenClaw usage-cost, Hermes profile SQLite and DeepSeek Harness projection-cache sources use bounded provider concurrency and preserve source cursors and failure status. Git insight collection uses refs/HEAD fingerprints and bounded log output; identity discovery and commit reclassification are committed with usage rollups. The active `refreshDiscovery` route now gathers scan-root candidates, all nine Agent discovery sources, allowlisted home assets, skill-library assets and installation status from the TypeScript backend; the Rust discovery method remains available only for migration comparison and has no production route. A narrow Rust notification only invalidates remote session-cache snapshots until the gateway moves in batch 7. Enabled scan-root traversal, Codex state-database discovery, Claude history/index, Cursor workspace storage, OpenCode SQLite/legacy JSON, OpenClaw config/JSONL, Hermes profile/state, Grok Build sessions/archive, Antigravity's empty discovery source, DeepSeek Harness workspace storage, and the allowlisted home asset scans now run in TypeScript with path, link and private-file protections. The native asset inspector also runs in TypeScript; its Rust equivalent is retained only for migration comparisons. Codex, Claude, Grok Build, OpenClaw, Hermes, OpenCode and Antigravity metadata readers and the session write store own native refresh, partial-source retention and cache clearing in TypeScript. The five JSONL providers' event paging module also passes differential checks for bounded reverse reads, snapshot cursors, tool association and Codex turn/mirror metadata; Hermes SQLite event pages also match native high-water cursors and file/content anchors. OpenCode CLI metadata/event reads preserve output limits, timeout, integer millisecond timestamps and offset paging; command supervision cleans up descendants after wrapper exit. Windows Job Object and batch-shim handling require the batch 9 platform acceptance. Antigravity ACP transport and native metadata reads also pass Rust differential checks, including bounded pagination, verified workspace ownership, partial sources, read-only permission rejection and shared deadlines. Its replay parser and four immutable snapshots preserve message chunk identity, tool patches, attachment/loss handling, native cursor fallback and byte budgets. Public session event routing now runs in TypeScript: every request re-lists the indexed workspace and matches its salted session ID before globally resolving a native reference, so cached pages cannot bypass workspace ownership checks. Native session document readers for Codex, Claude, OpenCode and Antigravity now run through the TypeScript `sessions.readDocument` route with bounded source reads, loss tracking and sensitive-data redaction; Grok Build, OpenClaw and Hermes keep their existing unsupported behavior. Session handoff preview and continuation planning, ChangeSet/archive construction, validation and apply, archive integrity validation, CLI preparation and cross-platform interactive terminal launch now run in TypeScript. The MCP gateway configuration plan used by continuation remains in Rust until its batch 6 migration. Database migrations and remaining domain operations still run in Rust. Workspace mutations are serialized, use SQLite transactions and foreign keys, and are fenced across process crashes. Both processes share schema 15 and the existing `preferences.json`; the router serializes every settings writer across both processes. Requests are never replayed through the other backend after a failure.

The default `AGENTKIB_BACKEND_MODE=hybrid` uses both processes; set it to `rust` to run the existing backend alone. TypeScript uses Electron's bundled Node runtime and needs no separate Node installation. Native file replacement and rollback use the staged precompiled Koffi module, which is unpacked from ASAR for installed apps. `pnpm dev`, `pnpm build`, and `pnpm dist:electron` generate the shared protocol in `packages/runtime-protocol/src/index.ts` and stage the required native artifacts in the order defined by `apps/desktop/package.json`; do not hand-edit that generated contract or its re-export in `apps/desktop/electron/generated/runtime-protocol.ts`. Rust removal remains gated on complete feature migration and installer acceptance on macOS, Windows and Linux.

### Start development

```bash
pnpm dev
```

This launches **AgentKib Dev** with identifier `ai.agentkib.dev`. Its database, preferences, caches, MCP packages, and other application data are isolated from the stable `ai.agentkib` application. Development startup does not copy, migrate, or merge stable data.

On macOS, development data is stored under:

```text
~/Library/Application Support/ai.agentkib.dev
```

On Windows it is stored under `%LOCALAPPDATA%\ai.agentkib.dev`. Linux uses the corresponding system application-data location.

### Validation commands

Run the smallest checks relevant to the change. The full local baseline is:

```bash
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
pnpm format:check
pnpm lint
pnpm test
pnpm typecheck
pnpm build
```

Useful focused commands:

```bash
# Apply the configured TypeScript/React formatter
pnpm format

# Diagnose the Linux build environment without changing it
apps/desktop/scripts/diagnose-linux.sh --strict

# Diagnose Windows tools and network access from PowerShell
pnpm diagnose:windows
```

`pnpm test` builds the development Rust Runtime and the TypeScript backend before running Vitest, including differential tests against the actual Rust runtime with a temporary database. `pnpm build` produces application code for the current platform but does not create an installer.

### Package the desktop app

```bash
pnpm dist:electron
```

Packages are written to `apps/desktop/release-electron/`. Packaging prepares and verifies the platform quota sidecar, builds and stages the release Rust Runtime, builds the renderer and Electron processes, and invokes electron-builder.

Windows x64 quota collection uses the pinned Win-CodexBar 0.60.3 prebuilt console CLI. `pnpm quota:prepare` downloads its release ZIP, verifies the pinned SHA-256, and stages `codexbar-cli.exe` as `agentkib-quota-sidecar.exe`; it does not compile the collector with Cargo. The AgentKib Runtime still requires Rust. Windows ARM64 quota collection remains unavailable.

Do not publish local packages as official releases. Maintainers should follow the [release process](RELEASE.md), which defines version synchronization, immutable tags, signing, notarization, checksums, and platform artifacts.

### 架构

AgentKib 由多个协作部分组成一个桌面应用：

| 部分                  | 位置                                                          | 职责                                                                               |
| --------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Electron main process | `apps/desktop/electron/main/`                                 | 窗口生命周期、托盘、原生系统集成、更新、Runtime 托管和高权限 IPC                   |
| Electron preload      | `apps/desktop/electron/preload/`                              | 向 renderer 暴露收窄后的桥接接口                                                   |
| React renderer        | `apps/desktop/src/`                                           | 路由、界面、状态和用户交互                                                         |
| TypeScript backend    | `packages/backend/`、`apps/desktop/electron/backend-entry.ts` | 在可独立重启的 Electron utility process 中处理应用设置、工作区／发现写入及缓存读取 |
| Rust Runtime          | Cargo 包 `agentkib-runtime`                                   | 数据库升级、原生使用统计采集与剩余模块                                             |
| Quota sidecar         | 准备到 `apps/desktop/resources/quota/`                        | 分平台采集本机额度数据                                                             |
| Runtime protocol      | 由 `apps/desktop/scripts/generate-runtime-protocol.mjs` 生成  | 在开发和构建前保持 TypeScript 消息与 Rust 协议一致                                 |

Electron main process 会启动两个后端，并通过经过校验的 IPC 控制 renderer 的访问。迁移期间，`runtime-router.ts` 明确指定每个方法的归属。TypeScript 负责工作区新增／刷新／排除／恢复、扫描根目录管理、发现流程与入库／报告、缓存列表、应用偏好、引导状态和额度显示设置。TypeScript 也负责原生工作区资产扫描和 manifest 导入、九种 Agent 的有效上下文预览、诊断报告／摘要和修复计划、带备份与回滚的审查变更套用、资产与记忆操作、Git 概况／历史／文件／差异、会话缓存列表／状态与七种 Provider 的原生事件读取、统计採集和增量匯入、Git 提交／身分統計、统计缓存视图与分类、成就读取／解锁状态写入和 Git 身份设置。Codex 采集器以带盐档案／数据库身份建立 checkpoint，增量读取 JSONL 尾段，在截断或替换时重建来源，并将 last-good 资料、检查点和统计事件放在同一事务写入。Claude stats-cache、OpenClaw usage-cost、Hermes profile SQLite 和 DeepSeek Harness projection-cache 采集使用有界并发并保留来源 cursor 与错误状态。Git 洞察采集使用 refs／HEAD 指纹及有界提交历史输出，并在同一交易写入身份发现、提交重分类和每日统计。Git 指令采用异步回覆、输出上限和超时。原生 discovery snapshot 和七种 Agent 的原生会话索引读取、会话事件及文档读取均由 TypeScript 正式路由执行；Rust discovery 和资产检查仅保留迁移比对用途。索引保留部分来源的 last-good 资料、失效及清除语义。五种来源的 JSONL 事件分页模块保留反向有界读取、快照游标、工具关联与 Codex 回合／镜像中继资料；Hermes SQLite 事件页保留原生高水位游标、文件身份与内容锚点；OpenCode CLI 中继资料／事件读取保留输出上限、超时、整数毫秒时间与 offset 分页，程序管理会在主程序退出后清理子程序。Windows Job Object 与 .cmd 启动仍需第 9 批平台验收。Antigravity ACP 传输、回放解析与不可变快照保留有界分页、工作区归属、讯息 chunk 身分、工具补丁、附件／损失处理、原生游标回退及字节预算。交接预览和续接规划、ChangeSet／archive 规划与写入、审查套用、封存验证及跨平台互動终端启动已由 TypeScript 执行；续接所需的 MCP gateway 设定计划归第 6 批迁移。数据库升级和剩余领域操作仍由 Rust 负责。工作区变更统一排队，使用 SQLite 事务和外键，并在后端崩溃时中止未完成的扫描写入。两个进程共享 schema 15 及现有 `preferences.json`，router 会对两个进程的全部设置写入统一排队；失败的请求不会交给另一个后端重复执行。

默认 `AGENTKIB_BACKEND_MODE=hybrid` 使用两个进程，设为 `rust` 可仅使用现有后端。TypeScript 使用 Electron 自带的 Node runtime，不需要另装 Node。原生文件替换和回滚使用暂存的 Koffi 预编译模块，安装版会从 ASAR 解包该模块。`pnpm dev`、`pnpm build` 和 `pnpm dist:electron` 会按照 `apps/desktop/package.json` 定义的顺序生成 `packages/runtime-protocol/src/index.ts` 中的共享协议，并暂存所需原生产物；不要手工编辑该生成协议或 `apps/desktop/electron/generated/runtime-protocol.ts` 中的转出文件。完成全部功能迁移，并通过 macOS、Windows、Linux 安装包验收后，才会移除 Rust。

### 启动开发环境

```bash
pnpm dev
```

该命令启动 identifier 为 `ai.agentkib.dev` 的 **AgentKib Dev**。它的数据库、偏好、缓存、MCP 包及其他应用数据与正式版 `ai.agentkib` 隔离。开发启动不会复制、迁移或合并正式版数据。

macOS 开发数据位于：

```text
~/Library/Application Support/ai.agentkib.dev
```

Windows 位于 `%LOCALAPPDATA%\ai.agentkib.dev`，Linux 使用对应的系统应用数据目录。

### 验证命令

优先运行与改动范围最相关的最小检查。完整本地验证基线为：

```bash
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
pnpm format:check
pnpm lint
pnpm test
pnpm typecheck
pnpm build
```

常用专项命令：

```bash
# 按项目配置格式化 TypeScript/React
pnpm format

# 只读诊断 Linux 构建环境
apps/desktop/scripts/diagnose-linux.sh --strict

# 在 PowerShell 中诊断 Windows 工具和网络
pnpm diagnose:windows
```

`pnpm test` 会先构建开发版 Rust Runtime 与 TypeScript 后端，再运行 Vitest；其中包含使用临时数据库与实际 Rust Runtime 比对的迁移测试。`pnpm build` 只构建当前平台的应用代码，不生成安装包。

### 打包桌面应用

```bash
pnpm dist:electron
```

产物写入 `apps/desktop/release-electron/`。打包过程会准备并校验当前平台的 Quota sidecar、构建并暂存 release Rust Runtime、构建 renderer 与 Electron 进程，最后调用 electron-builder。

Windows x64 额度采集使用固定版本的 Win-CodexBar 0.60.3 预编译控制台 CLI。`pnpm quota:prepare` 下载发布版 ZIP、校验固定的 SHA-256，并将 `codexbar-cli.exe` 暂存为 `agentkib-quota-sidecar.exe`，不再通过 Cargo 编译采集器。AgentKib Runtime 目前仍需要 Rust；Windows ARM64 的额度采集仍不可用。

不要把本机包作为正式版本发布。维护者应遵循[发布流程](RELEASE.md)，其中定义了版本同步、不可变标签、签名、公证、校验文件和各平台产物。
