## 修复

1. Cursor 测试 `Fixture.source` 只在 macOS 用于来源保护，非 macOS 的 all-targets Clippy 报 dead-code。字段及初始化项收窄为 `cfg(macos)`；来源文件仍在全部平台生成，非 macOS 的能力门限断言保留。
2. CI 新版 Rust 对 `AtomicU64.fetch_update` 发出 deprecated 错误，本机 1.92 不触发。Web worker 改为 `SeqCst` 的 `load / compare_exchange_weak` 循环，保留只读容量 32、mutation 仅空闲认领和投递失败回退。没有降低 Clippy 门限或使用 allow 屏蔽。
3. Windows 的两个 Cursor 集成用例等待 RPC 时返回 `Disconnected`，原 stderr 被丢弃，不能确定请求阶段或具体系统错误。fixture 的 `env_clear` 移除了 Windows 系统环境；现在只在 Windows 恢复宿主 `SystemRoot`，保留隔离 HOME / USERPROFILE / APPDATA / LOCALAPPDATA 和空 PATH，并将合成子进程 stderr 继承到测试输出。Windows 最终效果需由新 CI 验证。

Windows 系统库环境是候选原因：Microsoft 说明 Winsock provider 路径可含 `%SystemRoot%` 并在加载时展开；Runtime 的 MCP Hub 初始化包含 TCP 监听绑定。旧日志缺少 stderr，不能据此声称已观察到特定 Winsock 错误。[官方说明](https://learn.microsoft.com/en-us/windows/win32/api/ws2spi/nf-ws2spi-wscinstallprovider)
