## 本轮确认及修复

1. Web runtime 在 owner 最后一次刷新后缺少索引／工作区授权复验。新增可失败首写检查，live 返回前同样复验；撤销发生于等待期间时不派发控制。
2. 原生 remote 连接超时／撤销会释放连接许可，但后台阻塞读取仍继续。独立读取许可随实际工作持有，防止超时后新批次绕过读取并发上限。
3. Web 重复点击已选会话只递增 generation、未重建 SSE，导致后续状态和撤销事件被忽略。重复选择保持原订阅，回归覆盖状态及撤销。
4. HTTP 对无法关联的否定控制回执保留 fence 却仍返回 200，浏览器误显示已接收。非明确接受结果返回 502／unknown；send 和 approve 均覆盖异常字段矩阵。
5. 工作区会话按标题筛选后点击来源会话，目标被旧筛选立即排除。显式来源跳转清理筛选；测试先复现跳转失败再验证修复。
6. Web 管理页在撤销等待期间启动的旧轮询，晚到时可恢复已撤销设备的显示。操作结束递增状态版本，过期轮询成功／失败均不覆盖新结果；测试先复现撤销后设备重新出现。
7. 原生菜单／快捷键刷新仅调用本机目录刷新。统一调用本机与远程的刷新入口，回归覆盖本机索引关闭时远程目录更新及历史版本递增。
8. OpenClaw 兼容记录中的多工具块未适配反向读取顺序，返回时 A/B 变为 B/A。按块反向入队，保持返回顺序及事件 ID。
9. 同一项目根的多个已登记目录刷新时争用全局会话 ID。为 OpenClaw／Hermes／Grok Build 确定唯一代表，缓存迁移保留 ID；补刷新顺序、根新增／删除、部分刷新、嵌套项目隔离及原错误状态保留回归。初版补丁的部分刷新删缓存风险在交叉复审中发现并修正。
10. Codex 缺字段旧数据库使其他有效数据库的列表及正文读取一并失败。改为跳过不兼容 schema 并返回 partial；实际损坏数据库的原有报错行为不变。
11. Hermes profile 枚举错误被吞，可能导致部分结果作为完整快照删除缓存。传播 incomplete；目录不存在仍是正常空来源。
12. Codex 空白 source 被视为“存在”，阻止 header 分类回退。空白视为缺失；非空未知／畸形字段仍保守处理。第 10–12 项均先取得失败回归，再修复通过。
